# Docs Spec: Design System (Themes)

## Purpose
Describes the Design System page — textual-js's theme-based styling system: the `Theme` object, base colors, generated shades, derived variables, and the mechanism for swapping themes at runtime.

## Audience
App authors customising their app's appearance, theme authors contributing new palettes, and widget authors who need to know which theme variables to target.

## Required sections
1. Overview — themes map variable names to colors; those variables are consumed by TCSS (and content markup). Swapping a theme triggers a full re-render.
2. Themes — the `Theme` object shape (a `{ name, primary, secondary, accent, foreground, background, success, warning, error, surface, panel, dark, variables? }` record) and how to switch the active theme (via the command palette at runtime or by setting `app.theme`).
3. Registering a Custom Theme — constructing a Theme, calling `app.registerTheme(theme)` (typically in an `onMount`-equivalent hook), and then assigning `app.theme` to its name.
4. Base Colors — only `$primary` is required; Textual derives defaults for any omitted base color. Table of the 11 base variables with their intended uses (`$primary`, `$secondary`, `$foreground`, `$background`, `$surface`, `$panel`, `$boost`, `$warning`, `$error`, `$success`, `$accent`).
5. Shades — 3 lighter and 3 darker shades per base (`{color}-lighten-1..3`, `{color}-darken-1..3`).
6. Light vs. Dark Themes — the `dark` boolean on a theme flips `:dark`/`:light` pseudo-class matches and influences derived variables.
7. Text Colors — default (`$foreground`, `$foreground-muted`, `$foreground-disabled`), auto-contrast (`$text`, `$text-muted`, `$text-disabled`), and colored-text variants (`$text-primary`, `$text-secondary`, `$text-accent`, `$text-warning`, `$text-error`, `$text-success`).
8. Muted Colors — `$primary-muted`, `$secondary-muted`, `$accent-muted`, `$warning-muted`, `$error-muted`, `$success-muted`. Explain the "base blended with `$background` at 70% opacity" rule and the legibility guarantee.
9. Additional Theme Variables — a reference table grouped by subsystem: Border, Cursor (block), Input Cursor, Scrollbar, Links, Footer, Button. Each with default expression (e.g. `$block-cursor-background: $primary`).
10. App-Specific Variables — how an app can introduce its own variables (equivalent to overriding `getThemeVariableDefaults` — provide default values that a theme's `variables` dict can override).
11. Previewing Colors — the preview tool (if the textual-js CLI provides a `colors` or theme-preview command; otherwise omit with a note).

## Key concepts
- A theme is a plain data object; it does not contain behavior.
- Base color + dark flag + optional `variables` = a full palette. Missing bases are filled by framework defaults.
- Shades are generated; muted colors are generated by blending with `$background`.
- Derived variables (shades, muted, text-colored) can be overridden per-theme via the `variables` dict.
- App-specific variables provide a hook for app authors to define defaults that themes may optionally override.

## Behaviors and contracts
- Setting `app.theme` to an unregistered name raises an InvalidTheme error (see the App docs).
- Registering a theme replaces an existing theme with the same name.
- The `:dark`/`:light` pseudo-classes follow the active theme's `dark` flag.
- ANSI-color mode (see the App docs) is controlled separately; the `textual-ansi` theme automatically enables ANSI mode.
- Muted colors are constructed such that `$text-{color}` remains legible on them.

## Example requirements
Describe (do not inline) JSX/TypeScript examples covering:
- Defining a custom Theme object (with `variables` overrides) and registering it on mount.
- Switching the active theme by assigning `app.theme`.
- Consuming a derived variable in TCSS (`color: $text-accent;`).
- Overriding a per-subsystem variable (e.g. `$scrollbar`) inside a theme's `variables` dict.
- Defining app-specific theme variable defaults that themes may override.
All examples are JSX/TypeScript + TCSS; no Python.

## Notes for writers
- Do not describe Theme as a Python class import. In textual-js, Theme is a TS type/interface or a small helper constructor; describe the object shape.
- Do not reference `register_theme`/`unregister_theme` snake_case; use `registerTheme`/`unregisterTheme`.
- Do not demand a Python import line. Show a plain object literal (or a helper call) in JS.
- The "Previewing Colors" CLI may not ship in textual-js. If it ships, document the command name; otherwise omit or replace with "use the command palette's theme switcher."
- Muted colors being "blended with `$background` at 70% opacity" is a behavior description, not an API — do not expose a public blend function unless one exists.
- Avoid Rich `TerminalTheme` references. If ANSI-to-truecolor mapping is exposed to theme authors, describe the exposed shape (likely a plain object); otherwise skip.
